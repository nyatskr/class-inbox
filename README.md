# 课堂资料收件箱 · 本地原型 v1.0

> 导入完整课表，只追踪其中真正重要的课；每次上完课确认资料是否归档，晚上发现遗漏，期末按学科导出。
> 课程文件（PPT / PDF / Word / 实验报告）只存一份，可以关联到一节或多节课。
> 攒了太多旧课不想补？设一个「清账截止日」，之前的欠账一律免记。
> 每条记录带一份「课堂快照」：以后怎么改课表，已经发生过的课都不会变形。

纯本地网页，不需要小程序 AppID、不需要云开发、不需要服务器。
数据全部存在浏览器 IndexedDB 里，不上传任何地方。

```
class-inbox/
├─ index.html  styles.css  app.js     网页版（现在就能用）
├─ fixtures/                          样例课表，可直接导入试
├─ tests/                             E2E + 单元测试
├─ tools/                             样例课表的脱敏生成脚本
├─ miniprogram/                       小程序骨架（见 miniprogram/README.md）
└─ cloudfunctions/                    云函数：定时提醒 / 导入导出
```

## 快速开始

```bash
npm start              # 起本地服务，打开 http://127.0.0.1:8899/
# 或者不用 node：
python -m http.server 8899 --bind 127.0.0.1
```

> 数据按「访问地址」隔离，`127.0.0.1:8899` 和 `localhost:8899` 算两个站点。固定用一个地址打开。

跑测试（需要先装依赖）：

```bash
npm install            # 只装 playwright 一个 devDependency
npx playwright install chromium
npm test               # 顺序跑 tests/ 下全部
npm test 05            # 只跑文件名含 05 的
```

| 测试 | 内容 | 数量 |
|---|---|---|
| `01-library.js` | 学科资料库：上传 / 指纹去重 / 版本 / 关联多节课 / 导出目录 / 备份恢复 | 57 |
| `02-edge.js` | 边界：无课堂上下文上传 / 改类型 / 另存一份 / 旧版 JSON 备份 / 课表导入回归 | 17 |
| `03-debt.js` | 清账：一键免记 / 截止日记住 / 批量恢复 | 24 |

## 主流程

```
（可选）先对一遍作息表：节次 → 几点
  → 导入课表（Excel）
  → 预览：改名 / 取消勾选不要的课
  → 确认导入（二次导入自动去重，不重复建课）
  → 每天自动生成今日清单
  → 上完课：粘贴转录稿 / 传板书 / 或标记「无转录稿」
  → 顺手把老师的 PPT、实验要求挂到这节课（可选）
  → 20:30 只检查「今天 + 还没处理 + 没免记」的课
  → 补录往期漏掉的课（可选，见下）
  → 实在不想补的：设一个清账截止日，比它更早的一律免记
  → 期末按学科导出 ZIP
```

## 今日页那排数字怎么算

```
今天几节 = 今天课表上的全部记录
已处理   = 已上传转录稿 / 无转录稿 / 课程取消 / 免记   ← 都算「这节课不用再管了」
免记     = 只有真的标了免记时才多出这一格
待处理   = 剩下的，也就是晚间提醒会点名的那些
```

所以 `已处理 + 待处理 = 今天几节`，不会有一节看起来凭空消失。
进度条按「已处理 / 今天几节」走，全处理完就是 100%。

## 补录往期

首页底部有「＋ 补录往期记录」。点进去选日期 → 系统列出那天课表上的课 → 点一节填资料。

- 快捷选昨天 / 前两天，也可以翻日历补几周前的
- 那天的课**按课表列出来**，不要求之前生成过记录
- 课表里没有的（讲座、调课）走「没找到课程，手动选择」，选学科 + 节次即可
- 状态三选一：已上传转录稿 / 没有转录稿 / 暂时还没整理
- 粘了正文或加了照片但没点状态，保存时自动按「已上传转录稿」算
- 选了「已上传」但正文空着会被拦下来——空记录导出时没意义

**连续补录**：补录弹窗右下角进去，列出最近 7 / 30 / 90 天还没归档的课。
点一节补完自动回到列表，接着补下一节；也可以勾多节，一键「标记为无转录稿」。

列出最近区间内所有还没归档的课，按日期倒序。全部补完时显示「都补齐了 🎉」，
范围内课表本来就没课时显示「这段时间没有课，换个范围试试」。

## 清账：之前的欠账不补了

攒了太多旧课不想补，不用一条条点。今日页点「历史还有 N 节没归档 · 连续补录 / 清账 ›」，
列表底部有「更早的欠账不想补了？」——选一个日期，比它更早的待处理课一次性标记为**免记**。

- 默认日期是**上周一**，也就是「从这周开始正常记，之前的不算了」
- 点之前会先告诉你具体会忽略多少节（改日期，数字实时变）
- **不是删记录**：课还在「历史」里，筛「已免记」能看到，点一下就能单独恢复；
  筛出来之后还有「把筛出的 N 节恢复成待处理」，清账点错了不用一条条点回来
- 截止日记在 `settings.ignoreBefore`，**之后补录时新生成的更早的课会自动带上免记**——
  不会出现「清了账、下次点连续补录又冒出来一批」
- 已经归档 / 标记过无转录稿 / 课程取消的课不受影响

> 只想打勾、不想贴正文也可以：转录稿存在别处（ChatGPT、笔记软件、豆包自己的记录）时，
> 展开那节课直接点「已上传转录稿」就行，状态按钮是纯改状态，不强制贴正文。

## 上课日期 vs 上传日期

这是数据设计上的一条硬线，两个字段分开存：

| 字段 | 含义 | 什么时候变 |
|---|---|---|
| `sessions[].date` | **上课日期**，这份资料属于哪一天 | 创建时定下，永不修改 |
| `sessions[].uploadedAt` | **上传日期**，你什么时候把它补进系统 | 首次有内容时写入；清空后置 null |

后果：

- 导出 ZIP 的文件夹名和汇总表顺序都按 `date`（上课日期），不是补录时间
- 历史页里补录的记录会多一个「补录 10-28」小标签，一眼看出是事后补的
- **晚间提醒只查 `date === 今天`**。历史欠账单独算，在首页显示成「历史还有 N 节没归档」，
  点进去走连续补录。不会因为攒了三十节旧课，每晚被轰炸三十条。

## 课堂快照：课表改了，过去的课不变形

第二个硬线。`sessions` 除了 `entryId`，还存一份**当时的样子**：

```js
sessions[i].snap = {
  subjectId, subjectName, color,   // 学科名（学科改名也不影响历史）
  sections,                        // 第3-4节
  startTime, endTime,              // 10:00 / 11:40
  location, teacher                // 二区601 / 张老师
}
```

所有展示（今日卡片、历史列表、连续补录、提醒正文、导出 CSV / 资料目录）都读快照，
不再实时回查课表。于是：

| 你做的事 | 已经发生过的课 | 今天及以后的课 |
|---|---|---|
| 改教室 / 改节次 | 不变 | 跟着更新（`refreshSnaps`） |
| 删掉一条课表 | 保留，节次和地点都在 | 还没填内容的记录一起清掉，不留幽灵待办 |
| 同步替换导入 | 保留 | 文件里没有的安排被移除 |

规则一句话：**过去的不动，今天及以后的跟着课表走。**

老数据没有快照的，加载时会用「现在」的课表补一份（这是能拿到的最好版本），只跑一次。

## 历史记录

底部第四个 tab。可按学科、日期范围、转录稿状态、有无板书筛选，
结果按学科分组、组内按上课日期倒序。选中学科后可以直接「导出该学科 ZIP」。

## 学科资料库

转录稿和板书属于「某一节课」，PPT 和实验报告属于「整个学科」。这两件事混在一个列表里会很乱，
所以资料分成两层：

| 层 | 内容 | 归属 | 存在哪 |
|---|---|---|---|
| 课堂记录 | 转录稿 / 板书照片 / 当堂备注 | 一节课 | `sessions` |
| 学科资料库 | PPT、PDF、Word、实验报告、作业 | 整个学科，**可关联到 0..N 节课** | `files` |

每节课展开后底部有「相关课程资料」：

- **＋ 上传新文件** —— 传完自动挂到这节课，同时进学科资料库
- **＋ 从本学科资料库选择** —— 同一份 PPT 已经在库里，勾一下就关联上，**不复制第二份**

反方向也能操作：底部第三个 tab「资料」里，每个文件有「关联课堂」，
一次勾多节课（比如一份实验指导书关联第 3、5、7 周的实验课）。

### 一个文件只存一份

`files[]` 是唯一存字节的地方，关联关系记在文件上：

```js
files[i] = {
  id, subjectId,
  name, ext, size, kind,        // kind: ppt|doc|pdf|experiment|homework|other
  sha256,                       // 内容指纹
  rootId, version,              // 版本族：同一份文件的第几版
  links: [{ sid, note }],       // 关联到哪几节课
  createdAt, supersededBy?      // 有 supersededBy 就是历史版本
}
blobs[i] = { id, data: ArrayBuffer }   // 字节单独放这里，files 里不带
```

`sessions` 里**不存**文件列表——只有一份真源，不会出现「课上删了、库里还在」的错位。
删掉一节课时 `purgeSessionLinks()` 把关联摘掉，文件本身保留。

**字节和元数据分家**（v1.0 起，IndexedDB 升到 v3）：启动只读 `files`，
几十 MB 的 PPT 不进内存；只有下载 / 导出 / 备份时才 `await fileBytes(id)` 按需取。
攒到几百 MB 也不会一开页面就卡。

### 重复文件检测

上传时先算 **SHA-256 内容指纹**，不是只看文件名。命中时给出三个选择：

| 情况 | 选项 |
|---|---|
| 内容完全一致 | **关联已有文件到本节课**（推荐，不占空间）/ 保存为新版本 / 仍然上传为另一份 / 跳过 |
| 文件名相同但内容不同 | 保存为新版本（默认）/ 仍然上传为另一份 / 跳过 |

- 从「资料」页上传时没有课堂上下文，就不出现「关联已有文件到本节课」，只推荐「不用重复上传」
- 选「保存为新版本」时：新文件 `version+1`、**继承旧版本的全部关联**，旧版本打上 `supersededBy` 变成历史版本
- 选「仍然上传为另一份」时：两份互不相干，都是 v1（适合同一门课不同章节的 PPT 同名）
- 「资料」页有「版本 N」按钮，能看历史版本、下载旧版、把任意一版「设为当前」
- 环境不支持 `crypto.subtle` 时退化成 FNV-1a，指纹带 `w:` 前缀以示区分

### 类型与自动归类

按扩展名 + 文件名猜，猜错了在「资料」页点「改类型」：

| 类型 | 判据 | 导出到 |
|---|---|---|
| PPT / 讲义 | `.ppt .pptx .pps .odp .key` | `课程资料/PPT/` |
| PDF | `.pdf` | `课程资料/PDF/` |
| Word 文档 | `.doc .docx .wps .odt .rtf` | `课程资料/Word/` |
| 实验报告 | 上三类 + 文件名含「实验」「报告」 | `课程资料/实验报告/` |
| 作业 | 上三类 + 文件名含「作业」「习题」「练习」 | `课程资料/作业/` |
| 其他 | 兜底 | `课程资料/其他/` |

> v1 只做「文件类型 + 关联课堂」这一层。把一份实验报告再拆成「实验要求 / 实验数据 / 报告草稿 / 最终版」
> 需要每份文件单独的元数据，等真的用起来觉得不够再加。

## 导出的 ZIP

```text
高等数学/
├─ 汇总.csv                 ← 每节课一行，多了「资料数」列
├─ 资料目录.html            ← 哪个文件关联了哪几节课，可直接点开
├─ 课堂记录/
│  ├─ 2026-09-03/
│  │  ├─ 转录稿.md
│  │  ├─ 板书-01.jpg
│  │  ├─ 板书-02.jpg
│  │  └─ 相关课程资料.md     ← 这节课挂了哪些文件，相对链接指过去
│  ├─ 2026-09-10/
│  │  └─ 无转录稿.txt
│  └─ 2026-09-17/
│     ├─ 转录稿.md
│     └─ 备注.txt
└─ 课程资料/
   ├─ PPT/
   │  ├─ 第3章 树.pptx
   │  └─ 历史版本/
   │     └─ v1-第3章 树.pptx
   ├─ 实验报告/
   │  └─ 实验一 实验报告.docx
   └─ 作业/
      └─ 习题3.docx
```

关键点：**同一份 PPT 在 zip 里只出现一次**。课堂记录目录里不放副本，只写一个
`相关课程资料.md` 指向 `../../课程资料/PPT/xxx.pptx`。这样一门课几十节课共用一份 20MB 的 PPT，
导出包也只多 20MB，不是 20MB × 课次。

`资料目录.html` 是给人看的索引：按类型分组的文件表（大小、关联了哪几节课，可直接点开文件），
下面是按日期排的课堂记录表（转录稿链接、板书张数、资料数）。

ZIP 是手写的 store 模式打包器（无第三方库），中文文件名带 UTF-8 标记，
Windows 资源管理器 / macOS 归档工具 / Python zipfile 都能正常解开。

## 备份

「我的 → 全量备份」导出的是 **ZIP**，不是 JSON：

```text
data.json          ← 课表 / 记录 / 设置 / 文件元信息（不含字节）
files/<id>.bin     ← 每个课程文件的原始字节
```

课程文件是二进制，塞进 JSON 要 base64，白膨胀 1/3。导入时按扩展名自动识别，
**旧版的纯 JSON 备份仍然能导入**（只是里面没有课程文件）。

## 作息表（可编辑）

「我的 → 作息表 → 编辑」，逐节填上下课时间，可以增删节次、一键恢复默认。

出厂是常见的 12 节（08:00 起，午休 11:40–14:00，晚课 19:00 起）。你们学校不一样就改一次，
以后导入、手动加课、排序全部按你的作息表走。

### 时间从哪来：一份真源 + 三个派生字段

这是数据结构上最要紧的一条，也是为小程序迁移提前定下来的：

| 字段 | 性质 | 说明 |
|---|---|---|
| `entries[].sectionsKey` | **真源** | 纯 ASCII 的 `"3-4"`，匹配/去重/排序都用它 |
| `entries[].sections` | 派生 | 展示用，`第3-4节` / `第5节`，可随时重算 |
| `entries[].startTime` | 派生 | 由 `periods` 算出来 |
| `entries[].endTime` | 派生 | 同上 |
| `settings.periods[N-1]` | 配置 | `{ start:'10:00', end:'10:45' }` 即第 N 节 |

改作息表时 `recalcEntryTimes()` 会把所有课程的派生字段重算一遍，所以**不会出现「改了作息表，
旧课时间还是旧的」这种脏数据**。

例外：手动加课时勾了「这节课时间特殊，不跟作息表」的，会写成 `timeMode:'custom'`，
重算时跳过，永远保留你填的时间。

手动加课的表单也改成了选节次（第3节 – 第4节），选完直接把 `10:00–11:40` 显示出来；
真遇到调课、讲座这种不在作息表里的，勾一下自定义时间就行。

## 晚间提醒

每天过了设定时间（默认 20:30），只要今天的课还有没归档的，就推一条汇总。
**一条消息只报课程名 + 节次 + 地点，不含转录正文，不含板书照片。**

| 渠道 | 状态 | 成本 | 说明 |
|---|---|---|---|
| 微信 · Server酱 | 可用 | 免费 5 条/天 | 推到微信服务号，一天只发一条，够用 |
| 通用 Webhook | 可用 | 看你接什么 | POST JSON，可接企业微信机器人 / 钉钉 / Bark / 邮件网关 |
| 浏览器系统通知 | 可用 | 免费 | 只在页面打开时弹，不消耗额度 |
| 小程序订阅消息 | 规划中 | — | 要走微信订阅消息，得先迁到小程序 |
| 日历 .ics | 可用 | 免费 | 导进手机日历每天定点响，不依赖任何服务 |

### 配微信推送

1. 手机微信扫码登录 [sct.ftqq.com](https://sct.ftqq.com/sendkey)，复制 SendKey（`SCT` 开头）
2. 我的 → 晚间提醒 → 微信通知 · Server酱 → 开启 → 粘贴 SendKey
3. 点「发一条测试」，微信收到就通了

Key 只存本机 IndexedDB，不上传。推送走 `https://sctapi.ftqq.com/<KEY>.send`，
该接口对浏览器跨域开放（回显 Origin），所以**静态页面不需要任何后端**就能推。

推送内容长这样：

```text
标题：还有 1 节课没归档
正文：
2026-10-28 还有 1 节课没上传转录稿：

- 专业英语　第9-10节　三区303

补齐后今晚不会再提醒。本条只含课程名/节次/地点，不含任何转录正文或板书。
```

Webhook 收到的是同一份数据的 JSON：

```json
{
  "date": "2026-10-28",
  "count": 1,
  "title": "还有 1 节课没归档",
  "desp": "…markdown 正文…",
  "courses": [{ "name": "专业英语", "time": "第9-10节", "location": "三区303" }]
}
```

### 去重与补推

- 同一渠道**当天只推一次**，记在 `settings.pushSent[渠道] = 日期`
- 到点时页面没开，就在下次打开页面 / 切回前台时补推
- 「立即试推」手动发真实清单，**不占用**当天的去重标记，可以反复测
- 全部补齐后不再推

## 课表里的课 = 要追踪的课

没有「记录要求」这个概念了：**课表里留着的每一门课都要记录，不想要的直接删掉**。
所以今日清单 = 当天课表上的全部课程，晚间提醒也只盯这些。

某一节课特殊（比如高数这周只是答疑），在今日清单里展开那节课，点「本次免记」——
这一节立刻退出待办和提醒，但不影响这门课其他周次。

## 课表导入

点课表页的「导入课表」，支持四种文件，**按文件内容自动判断，不看扩展名**：

| 实际格式 | 说明 |
|---|---|
| `.xls`（BIFF8 二进制） | 学校教务系统导出的就是这种，用内置 OLE2 + BIFF 解析器读 |
| `.xlsx` | 新格式，zip + XML |
| HTML 表格伪装成 `.xls` | 很多教务系统这么干，按 GBK / UTF-8 自动解码 |
| `.csv` / `.tsv` | 纯文本兜底 |

内置两套版式：

1. **网格型**（教务系统最常见）：行=节次、列=星期，格子里是课程信息
   - 支持合并单元格：跨行的课程合成一段（如 `第1-4节`）
   - 节次列写「一/二/三」这种大节时，按「第1-2、3-4、5-6 节」展开
   - 一个格子里塞两门课、换教室分两条，都能拆开
2. **列表型**：表头含 `课程名称 / 星期 / 节次 / 周次 / 教室 / 教师`

课程格子里认这些写法：

```text
课程/周次/地点/教师/教学班/…        ← 斜杠分隔（你们学校是这种）
课程名 ⏎ 教师 ⏎ 1-16周 ⏎ 教三-201   ← 换行分隔（其他学校常见）
1-4周,7-17周   2-4周,7周,10-16周   ← 多段周次
(5-6节)10周                        ← 周次里带节次覆盖
1-16周(单)                         ← 单双周
```

**表尾的「本学期 2026-08-31 正式上课」会被自动识别**，导入时一并把学期开始日期设好——
这一步很关键，否则「第几周」会全错，当天该出现的课就不会出现。

解析完先进预览页，**不会直接写库**：

- 每行可以改名、取消勾选、直接删掉
- 勾上的都会进每日清单，不想要的就取消勾选
- 确认后按 `学科 + 星期 + 节次 + 周次` 去重：同一份表导第二次只更新不新增
- 二次导入按「学科 + 星期 + 节次 + 周次」匹配，不会重复建课

### 合并更新 / 同步替换

二次导入时有两条路，**默认合并更新**：

| 模式 | 行为 | 什么时候用 |
|---|---|---|
| 合并更新 | 只增加和更新，**不删**任何现有安排 | 又导了一份新表，先看看有没有变化 |
| 同步替换 | 这次文件里没有的、或取消勾选的课程，从课表里移除 | 学期中改选课 / 退课，想让课表跟教务系统一致 |

同步替换的两条边界：

- **只动文件里提到的课**。文件里压根没有的课程（比如自己手动加的）不归这次管，不会被误删
- 移除前会弹确认，列出前 8 条要删的安排和总数；已归档的历史记录不受影响（有课堂快照）
- 连带清掉这些课「今天及以后、还没填内容」的记录，否则会留下永远补不完的幽灵待办

目录里的样例：

- `fixtures/sample-timetable.xls` —— 学校导出格式的复刻版式，含合并单元格、双课程格、多段周次。**内容全部虚构**（课程名、教室、教师、教学班编号都换过），可直接导入试
- `fixtures/sample-timetable.xlsx` —— 通用网格版式

> 样例表由 `tools/gen-sample-timetable.py` 生成：保留原表版式和字段顺序，把所有可识别信息替换成虚构内容，所以解析器回归测试仍然有效。脚本读 `tools/.template.xls`（真实表，已被 .gitignore 排除，不会进仓库）。

> PDF 课表暂不做——图片型 PDF 要 OCR，错行漏字比手动改还费时。

## 已知边界

- 图片按最长边 1600px、JPEG 0.82 压缩后存 IndexedDB，单张约 200–400KB；iPhone 的 HEIC 原图浏览器解不开，需要先转 JPG
- **本地页面不能后台推送**：到点时页面没开，微信就收不到；下次打开会补推。要真正「关着也能收到」，得迁到小程序用云函数定时触发，或者用 .ics 兜底
- 系统通知依赖浏览器权限，页面关着不会响
- Server酱免费版每天 5 条；本应用一天最多 1 条，够用
- 通用 Webhook 的目标服务必须允许跨域（返回 `Access-Control-Allow-Origin`），否则浏览器会拦掉；服务端自己发不受此限
- 没有账号体系，换浏览器 / 换设备要手动「全量备份 → 导入」（备份含 SendKey，注意别乱发）
- 不解析 docx / pdf 正文（豆包里复制文字更稳）
- 卡片上显示的是**节次**（第3-4节）而不是具体时间——时间是从作息表推算的，具体几点看「我的 → 作息表」
- 作息表只做了「节次 → 时间」这一层，没有区分单双周的不同作息（比如有些学校周三下午不上课），需要的话再单独提
- 表尾的「其他课程：形势与政策5」这类没有固定星期的课不会导入，预览页会提示你
- 补录时那天的课是**按当前课表推算**的（星期 + 周次匹配）。如果学期中途改过课表，很早以前那几天可能对不上，用「手动选择」兜底
- 连续补录会为所选区间补齐课表记录（这是它列出清单的前提），所以第一次点「最近 90 天」会一次性生成较多记录，之后按需补即可

### 转录稿只能手动搬

**不能从豆包 / ChatGPT 的云盘自动导入**，原因有三层：

1. 豆包的录音转写记录存在它自己的账号里，**没有开放个人读取接口**（火山引擎有 ASR API，但那是「帮你做转写」，不是「读回豆包 App 已经记好的内容」）
2. 就算有接口，浏览器跨域调用还需要对方回 `Access-Control-Allow-Origin` + 一套 OAuth，静态页面拿不到
3. 网页也读不到别的 App 的云盘目录

所以转录稿还是「豆包里复制全文 → 粘进来」，或者「导出 txt/md → 导入」。
真要自动化，只有等它们开放 API，或者走「小程序 + 云函数」那条路自己接语音转写。

> 折中办法：转录稿在别处（ChatGPT / 笔记 / 豆包）的话，这节课**只点状态、不贴正文**就行，
> 系统只负责「记没记」这个勾，正文留在你习惯的地方。

### 课程文件这一块

- **单个文件上限 30MB**，超过会直接跳过并提示。PPT 一般 5–20MB，超了多半是嵌了视频，建议先精简
- 字节和元数据分家（`blobs` / `files`），启动不再把整个资料库读进内存；但**下载 / 导出 / 备份时仍要把字节读进内存**，所以一次性处理超大资料库会吃内存
- 文件字节存在 IndexedDB 里，浏览器配额通常几百 MB 到几 GB，但**不是永久保险**：清理浏览器数据、无痕窗口、系统空间紧张都可能丢。设置页有「申请常驻」按钮（`navigator.storage.persist()`），申请到之后浏览器不会主动清
- 所以**定期「全量备份」**。真要长期存几十门课的 PPT，还是应该转到云文件存储（见「下一步」）
- 导出打包时资料库超过 200MB 会提示「打包要一会儿」；再大就分学科导出
- 只做「存 + 关联 + 导出」，**不解析文件正文**，也不做 PPT 预览缩略图
- 同名不同内容的判定用的是「同学科 + 同文件名」，改过名字又改过内容就当成新文件了

## 搬到小程序（骨架已就位）

**迁移不只是换数据层**。HTML / CSS / DOM 事件 / IndexedDB / 文件选择 / 浏览器通知 / 下载
这些全要换成 WXML / WXSS / 页面生命周期 / 微信接口。能复用的是业务规则，界面层基本要重搭。

所以先把业务规则抽成了 `miniprogram/core/`（不依赖 DOM，也不依赖 wx API，Node 里能直接测），
再把 5 个页面和 5 个云函数搭起来。**现在能跑的是「今日清单改状态 + 传板书」和提醒链路，
课表解析器还没搬**——具体差什么见 [miniprogram/README.md](miniprogram/README.md) 末尾那张表。

数据层的对应关系：

| 现在 | 小程序版 |
|---|---|
| IndexedDB 六个 store | 云数据库六个集合，按 OpenID 隔离 |
| 页面内提示 + 浏览器通知 + 前端 POST Server酱 | 云函数定时触发器（真正的「关着也能收到」） |
| `compressImage()` + dataURL | `wx.cloud.uploadFile` 传云存储，库里只存 fileID |
| `files` + `blobs` 存元数据和字节 | `wx.cloud.uploadFile` 到云存储，`files` 只留 `fileID` + 元信息 |
| 前端 `makeZip()` | 云函数打包，返回临时下载链接 |
| 前端 `sha256Hex()` | 小程序端没有 `crypto.subtle`，改成 `wx.getFileInfo({digestAlgorithm:'sha256'})` 或上传后由云函数算 |
| 前端解析 xlsx | 同一个解析函数搬到云函数，或前端直传解析 |
| `settings.pushSent` 当天去重 | `reminder_logs` 集合，按 OpenID + 日期唯一索引 |
| `sessions[].date` / `uploadedAt` / `snap` | 原样搬。`snap` 是最该先定下来的字段，后补要写数据迁移 |
| `settings.periods` 存本地 | 同一个字段直接搬，云数据库里也只是一个数组 |
| 前端 `fetch` 直连 Server酱 | **SendKey 必须挪到云函数**，客户端只调自己的云函数；小程序还要配 `request` 合法域名，浏览器能跨域 ≠ 小程序能直连 |

### 订阅消息别想成「一次授权，永久每天提醒」

微信现在的规则是：**一次性订阅**通常一次授权只对应一次下发；**长期订阅**只对特定类目和模板开放。
教育类目虽然在列表里，但「个人课堂整理工具」能不能拿到长期模板，事先没法保证。

所以小程序版建议主次分明：

```text
主提醒：云函数每天 20:30 检查 → Server酱推到微信（不依赖订阅消息额度）
可选：小程序订阅消息 → 等申请到合适模板再开，作为补充
```

云函数的定时触发器**可能重复触发**（官方有提醒），所以云端去重表必须照旧：
按「用户 + 日期 + 渠道」唯一，别指望定时器只跑一次。

### 老师微信发来的 PPT 反而更好办

小程序有 `wx.chooseMessageFile`，可以直接从微信会话里挑文件上传——这比手机网页强，
网页要先把文件存到相册/文件App 再选。做小程序版时这是值得专门做的一条路径。

### 现在要不要马上迁

| 阶段 | 判断 |
|---|---|
| 网页个人试用 | 可以 |
| 建小程序骨架 | 可以 |
| 接云数据库 / 云存储 | 可以（`snap` 已经就位，不用再改数据结构） |
| 发布给自己长期用 | 先按真实课表连用一两周再说 |
| 提交公开审核 | 暂时不建议 |

真正麻烦的是「以后改数据结构」，所以现在最值得先钉死的是：`sessions[].snap`、
`files` 的 `sha256 + rootId/version + links`、`date` 与 `uploadedAt` 分离、`exempt` 与 `ignoreBefore`。
这几样定了，界面怎么改都不痛。

表结构：`subjects` / `schedule_entries` / `class_sessions`
（含 `status`、`exempt` 单次免记、`snap` 课堂快照）/ `files`（含 `sha256`、`links[]`、`rootId/version`）/ `settings` / `reminder_logs`。
